# Hand-tuned assembly for rktcrypto (AArch64)

Performance-critical inner kernels written in **asmp** — an ARM64 assembler
(S-expression / annotated-GNU syntax with virtual registers, graph-colouring
register allocation, and ABI-aware prologue/epilogue) kept at
`/Users/cutiedeng/Y2026/M05/D29/asmp.git`.

## Build-time independence

The asmp tool is a **development-time** dependency only. Each kernel is
committed in two forms:

- `asm/<name>.asm` — the asmp source (edited / generated by hand).
- `rktcrypto_<...>.S` — the assembler output, wrapped in a preprocessor
  guard, **committed and compiled directly by the normal build**
  (`build.zuo`). The build never invokes asmp or Racket.

So a fresh checkout builds with only a C toolchain; asmp is needed only to
*regenerate* a `.S` after changing a `.asm`.

## Kernels

| kernel | source | generated | routed from |
|--------|--------|-----------|-------------|
| generic Montgomery multiply (CIOS) | `asm/mont_mul.asm` (`asm/gen_montmul.py`) | `rktcrypto_p256_asm.S` | `mont_mul` dispatch (mod n) |
| P-256 field multiply (interleaved CIOS) | `asm/mont_mul_p256.asm` (`asm/gen_montmul_p256.py`) | `rktcrypto_p256_asm.S` | `mont_mul` dispatch (mod p) |

Both live in one committed `.S` (the `.asm` sources are concatenated before
assembling). `rktcrypto_p256.c`'s `mont_mul` dispatch picks by ctx:

- `mont_mul_p256(r,a,b)` — **field prime p** (all point arithmetic).
  Interleaved CIOS (OpenSSL ecp_nistz256-armv8 structure): 4 iterations of
  {multiply-accumulate one word of b, then reduce}, keeping the accumulator
  at 6 words. Because n0 = 1 for p and p has Solinas limbs, each reduction is
  9 instructions (lsl/lsr + subs/sbc + 5 adds) — no reduction multiply.
  ~147 instructions vs an SOS full-product's ~235; **170 Mmul/s throughput
  (independent muls) vs SOS 97**, the number point arithmetic actually hits.
  Squaring routes here too (mont_mul_p256(a,a) = 150 Msq/s, beats a separate
  SOS symmetric squarer).
- `mont_mul_asm(r,a,b,ctx)` — **group order n** (scalar ops). Generic CIOS
  reading ctx->m/ctx->n0. 2.1x the C.

Key lesson (measured): on the wide OoO M1 core the field multiply is
*latency-bound* on the serial carry chain when muls are chained, but point
arithmetic runs *independent* muls, so **throughput** is what matters — and
the interleaved CIOS's lower instruction count wins there even though its
chained-latency is similar to SOS. The ctx pointer is a compile-time
constant at essentially every call, so the dispatch branch folds under
inlining.

## Regenerating a kernel

```sh
ASMP=/Users/cutiedeng/Y2026/M05/D29/asmp.git
# 1. (re)generate the asmp source if it is script-produced
python3 asm/gen_montmul.py asm/mont_mul.asm
# 2. assemble to Apple AArch64 syntax
racket $ASMP/cli/as.rkt --gnu-input --apple --elim --default-abi aapcs64 \
    -o /tmp/body.s asm/mont_mul.asm
# 3. wrap in the platform guard and commit as the .S
{ printf '#if defined(__aarch64__) && defined(__APPLE__)\n'; cat /tmp/body.s; \
  printf '\n#endif\n'; } > rktcrypto_p256_asm.S
```

Add `--debug-reg-map` (allocation map) or `--dump=interference` (conflict
graph) when tuning register pressure.

## Verification discipline (mandatory)

Assembly is **never** committed without passing, against the portable C as
oracle:

1. **Bit-exact differential** over ≥200k random inputs incl. edge cases, for
   every modulus/parameterisation the kernel serves.
2. **ABI clobber guard** — callee-saved x19–x28 (and v8–v15) must survive a
   call (sentinel check).
3. End-to-end: the built binary passes `crypto-subsystem-self-test?`, the
   P-256 consistency sweep, and the OpenSSL differential.

The pilot harness lives under the scratchpad (`montmul_test.c`): oracle =
`mont_mul_portable`, subject = `mont_mul_asm`.

## Portability

`rktcrypto_p256_asm.S` is guarded `#if defined(__aarch64__) &&
defined(__APPLE__)` and matches the routing guard in `rktcrypto_p256.c`. On
every other target the object is empty and P-256 uses `mont_mul_portable`. A
GNU/ELF AArch64 variant (for aarch64-linux) is a straightforward follow-up:
emit with `--gnu` and widen the guard.
