# asmp zstd01

`zstd01` is the first Zstandard product line for asmp. It currently writes
valid zstd frames with raw and RLE blocks, then verifies them with libzstd.

Current support:

- single-shot compression entry
- standard zstd magic and frame header
- single-segment frames with content size
- raw blocks up to 128 KiB
- RLE blocks for all-equal block payloads
- experimental compressed blocks with raw literals and zero sequences
- experimental one-sequence RLE tables for short all-equal inputs
- experimental one-byte ML extra bits for all-equal inputs up to 259 bytes
- experimental multi-byte ML extra bits for all-equal inputs up to 128 KiB
- experimental single-sequence prefix-literal plus offset-1 repeated suffix
- experimental predefined-FSE short single-match sequence blocks
- experimental multi-sequence RLE-mode blocks for fixed four-byte runs
- experimental fixed-width multi-token RLE-mode sequence store
- experimental fixed-width multi-token blocks with zstd last literals
- experimental predefined-LL two-sequence store
- no dictionary, checksum, streaming, Huffman literals, general FSE sequence
  section, or match finder yet

Build:

```sh
racket lib/zstd01/build.rkt --install
```

The default install prefix is `lib/zstd01/build/install`.

Generated install layout:

```text
include/asmp_zstd.h
lib/libasmp_zstd.a
lib/pkgconfig/asmp-zstd.pc
```

Verify:

```sh
racket lib/zstd01/render-header.rkt --check
raco test lib/zstd01/test
```

The C example in `lib/zstd01/c-examples/roundtrip.c` links against libzstd
only for validation: asmp writes the zstd frame, libzstd decodes it.

The stable `asmp_zstd_compress_default()` entry still chooses raw/RLE frame
blocks. The experimental `asmp_zstd_compress_litonly()` entry writes zstd
compressed blocks with a raw-literals section and `Number_of_Sequences = 0`.
It uses a non-single-segment frame with a 128 KiB window because compressed
block payloads can be larger than the regenerated byte count.

The experimental `asmp_zstd_compress_seqrle()` entry writes a real zstd
sequence section for repeated-byte inputs of length 4..35. It emits one raw
literal and one match sequence using LL/OF/ML RLE tables, then falls back to
the literal-only compressed block path for other inputs.

The experimental `asmp_zstd_compress_seqrle_wide()` entry extends that same
shape to repeated-byte inputs of length 4..259. It supports ML code extra bits
that still fit in one sequence bitstream byte; longer matches continue to use
the literal-only fallback.

The experimental `asmp_zstd_compress_seqrle_full()` entry keeps the same
single-sequence RLE shape, but writes a multi-byte sequence bitstream for ML
extra bits. It covers repeated-byte inputs through one 128 KiB zstd block and
falls back to literal-only blocks for other inputs.

The experimental `asmp_zstd_compress_singlematch()` entry adds a tiny parser
for inputs that start with 1..15 literal bytes and then continue as repetitions
of the last literal byte. It emits one sequence with offset code 0 and falls
back to literal-only blocks for other inputs.

The experimental `asmp_zstd_compress_predef_singlematch()` entry uses zstd
Predefined_Mode for LL/OF/ML tables when that same single-match shape has no
extra bits: prefix length 1..15 and match length 3..34. Other inputs fall back
to the `singlematch` encoder.

The experimental `asmp_zstd_compress_multirle()` entry writes the first
multi-sequence compressed block. It recognizes 2..31 four-byte repeated runs,
stores one literal byte per run, and emits repeated RLE-mode sequences with
`LL=1`, `OF=0`, and `ML=0`. Other inputs fall back to `predef_singlematch`.

The experimental `asmp_zstd_compress_multitoken()` entry extends that idea to
2..15 fixed-width five-byte tokens shaped as `x yyyy`. It stores two literal
bytes per token and emits repeated RLE-mode sequences with `LL=2`, `OF=0`, and
`ML=0`. Other inputs fall back to `multirle`.

The experimental `asmp_zstd_compress_multitoken_tail()` entry keeps the same
fixed-width token shape, but allows 1..11 trailing literal bytes after the
matched token region. Those bytes are emitted as zstd last literals after the
sequence stream. Other inputs fall back to `multitoken`.

The experimental `asmp_zstd_compress_predef_seqstore()` entry handles one
fixed two-sequence shape: four copies of one byte followed by one literal byte
and four copies of another byte, such as `aaaabcccc`. It stores three raw
literals, emits sequence LL symbols `1` and `2` with zstd Predefined_Mode, keeps
OF/ML in RLE_Mode, and falls back to `multitoken_tail` for other inputs.
